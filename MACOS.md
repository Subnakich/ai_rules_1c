# macOS: исходники локально, 1С на сервере

Mac хранит Git-проект и запускает ИИ-клиент. Платформа, база, выгрузка конфигурации
и серверные службы остаются на удалённой машине. Windows-скрипты работы с базой
не становятся совместимыми с macOS от установки PowerShell.

## Установка правил

Нужны Git и PowerShell 7 (`pwsh`). Установите PowerShell по
[инструкции Microsoft](https://learn.microsoft.com/powershell/scripting/install/install-powershell-on-macos)
для своей архитектуры — Apple Silicon или Intel. Python 3 и `lxml` нужны отдельно
для поставляемых Python-инструментов XML, если вы ими пользуетесь.

```sh
git clone https://github.com/Subnakich/ai_rules_1c.git ~/Documents/ai_rules_1c
cd /путь/к/проекту-1с
~/Documents/ai_rules_1c/install.sh init -Tools codex -PlatformMode remote -NonInteractive
```

Вместо `codex` можно указать `cursor`, `claude-code` или другой адаптер из README.
Путь к проекту может содержать пробелы; заключайте его в кавычки. Для явного
выбора каталога добавьте `-ProjectRoot "/путь/к/проекту"`. Установка только правил
не требует локальной 1С, работающей базы или доступного MCP.

Адаптер Codex также устанавливает команды в пользовательский `~/.codex/prompts/`,
как и исходный проект. Установка и обновление соблюдают существующий механизм
разрешения конфликтов; проверьте вывод при наличии своих команд.

## Настройка подключений

Установщик сохраняет `PLATFORM_MODE=remote` в `.dev.env`. В нём же укажите
реальные URL тех MCP, которые уже развёрнуты и доступны с Mac, например:

```dotenv
PLATFORM_MODE=remote
MCP_URL_1C_CODE_METADATA_MCP=https://mcp.example.org/metadata/mcp
MCP_URL_1C_SYNTAX_CHECKER_MCP=https://mcp.example.org/syntax/mcp
MCP_URL_1C_DOCS_MCP=https://mcp.example.org/docs/mcp
```

Адреса выше — примеры, это не готовый публичный сервис. Полный список ключей
есть в `.dev.env.example`. Порты и пути берутся из вашей серверной установки.
Для готового SSH-туннеля можно явно задать `http://127.0.0.1:<порт>/mcp`.
Пароли в URL не поддерживаются; используйте механизм аутентификации клиента.
Не отключайте серверную аутентификацию ради подключения.

`INFOBASE_PUBLISH_URL` задаётся отдельно для веб-клиента и автоматически
формирует URL `1c-data-mcp`. `MCP_URL_1C_DATA_MCP` позволяет переопределить именно
MCP-адрес, например при reverse proxy. В remote незаполненные MCP пропускаются,
поэтому до настройки их отсутствие ожидаемо. Автоматически настроенные внешним
дистрибутивом MCP-конфиги продолжают обслуживаться этим дистрибутивом.

После изменения адресов:

```sh
~/Documents/ai_rules_1c/install.sh update -NonInteractive
~/Documents/ai_rules_1c/install.sh doctor
```

Перезапустите ИИ-клиент и проверьте список доступных инструментов. `doctor`
проверяет установленный набор файлов, а не доступность базы и успешность деплоя.
`PLATFORM_PATH` на Mac оставьте пустым. Параметры запуска платформы заполняются
в серверном проекте, из которого реально выполняются эти операции.

## Работа с исходниками и базой

- Получайте исходники через согласованный Git-процесс или выгрузку на сервере
  с последующим переносом. Установка правил не выполняет синхронизацию.
- Для MCP с файловыми аргументами настройте соответствие путей Mac, сервера и
  контейнера и подтвердите одинаковую версию исходников. Путь `/Users/...`
  не становится автоматически доступным удалённому MCP.
- Загрузка, выгрузка, сборка и тесты базы требуют настроенного доступа к
  серверному исполнителю. Само MCP-подключение не предоставляет SSH или Designer.
  Пока исполнителя нет, агент готовит процедуру и сообщает, что она не выполнена.
- Регулярную выгрузку на Windows-сервере выполняет его планировщик. Создавать
  задачу `launchd` на Mac для такой схемы не требуется.

Поддержка этой схемы не означает полного порта всех локальных инструментов 1С
на macOS. Установщик, формирование удалённых MCP-конфигов и правила маршрутизации
проверяются автономно. Живые операции требуют проверки с вашей серверной средой.

## Обновление и откат

Обновляйте клон из **этого форка**, затем запускайте `install.sh update` из проекта.
Собственные изменения в управляемых файлах сохраняются по правилам установщика;
не добавляйте `-Force` без просмотра конфликтов. `install.sh remove` использует
штатное удаление управляемых правил; пользовательские исходники и база в него
не входят. Для отката версии используйте проверенную ревизию клона и `update`,
предварительно сохранив изменения проекта в Git.
